# Berlin Café Opportunity Modelling - Thesis Project

A reproducible pipeline for predicting popular café density per H3 hexagon in Berlin, and identifying opportunity gaps between predicted and actual density.

## Structure

- `src/` - reusable pipeline modules (import these in notebooks, don't duplicate logic)
- `notebooks/`- one notebook per phase, numbered in execution order
- `config.py`- canonical reference values (H3 resolution, thresholds, buffer distances, seed, CRS) - see Reproducibility notes below
- `data/` - **gitignored**. Raw/processed data lives here locally and goes to the submission Drive folder, but never to GitHub (company-provided café data is not public)
- `outputs/` - figures, tables, maps, saved models generated by notebooks
- `docs/decision_log.md` - running log of methodological pivots (feeds Methodology/Discussion chapters)
- `requirements.txt` - pinned package versions for reproducibility

## Setup

1. Clone the repo and set up the environment:

git clone <repo-url>
cd berlin-cafe-thesis
python -m venv venv
venv\Scripts\activate # Windows
pip install -r requirements.txt


2. Create the required data/output folders (not included in the repo — `data/` is gitignored, and some `outputs/` subfolders are only auto-created partway through the notebook sequence):

mkdir data\raw data\external data\processed
mkdir outputs\models outputs\figures outputs\tables outputs\maps


3. Place the required raw data files (not distributed in this repo - see "What goes where" below):
   - `data/raw/berlin_cafes.csv` - raw café export
   - `data/external/berlin_boundary.csv` - Berlin boundary (WKT)
   - `data/raw/grid_1km.csv` - Eurostat population grid

4. Run the notebooks in order - each one depends on outputs saved by the ones before it:
   `01` → `02` → `03` → `04` → `05` → `06` → `07` → `08` → `09` → `10`

   Note: notebook `04` queries OpenStreetMap's Overpass API live via `osmnx` and needs an internet connection - no API key required, but it can take a few minutes depending on server load. All other data sources are read from local files.

## Reproducibility notes

- `config.py` documents the canonical values used throughout the pipeline (H3 resolution, popularity thresholds, buffer distances, random seed, CRS). Notebooks and `src/` modules currently set matching literal value directly rather than importing from it - these were
  manually checked against `config.py` and confirmed consistent.
- `random_state=42` is used for the main train/test split and model fits (notebook 07); the inner validation split used for hyperparameter tuning intentionally uses a different seed
  (`7`), to avoid correlated randomness between the two splits.
- `h3` v4 API used throughout (`h3.latlng_to_cell`, `h3.cell_to_boundary`, `h3.polygon_to_cells`) 

NOTE: Raw café data was obtained via institutional access and is not included in this repo
